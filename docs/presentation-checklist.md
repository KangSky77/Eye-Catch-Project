# 10월 21일 발표 전 확인

## 실행

프로젝트 루트의 `Start-EyeCatch.cmd`를 실행하거나 PowerShell에서 `./start.ps1`을 실행합니다.
기존 앱이 실행 중이면 재사용하며 다른 프로그램을 종료하지 않습니다. 기본 주소는
`http://127.0.0.1:8001/`입니다. Ollama가 로컬 주소로 설정돼 있고 설치돼 있으면 함께 시작합니다.
모델은 자동으로 다운로드하지 않습니다. 사진·AI 준비 상태는 첫 화면에서 각각 확인합니다.

```powershell
.\.venv\Scripts\python.exe scripts\presentation_preflight.py
```

준비됨은 사진 모델과 AI 모델 설치·연결 확인입니다. 실제 AI 생성과 PDF 성공은 아래 시연으로 확인합니다.
AI가 연결되지 않아도 사진 분석과 결과 화면은 유지되며, 연결을 복구한 뒤 AI 설명을 다시 요청할 수 있습니다.

## 휴대폰과 실제 발표 PC

- 첫 화면 → 수술 여부 → 촬영 안내 → 사진 선택 → 암슬러 양쪽 눈 → 문진 → 결과 → AI 설명 → PDF.
- 갤러리 사진 선택과 카메라 촬영을 각각 확인합니다. 권한 거부·파일 선택 취소 뒤 다시 시도합니다.
- 흐린 사진·어두운 사진·눈이 아닌 사진에서 재촬영 안내가 나오는지 확인합니다.
- 검사 중 뒤로가기·언어 변경·큰 글씨·회전에서 입력과 결과가 유지되는지 확인합니다.
- AI 응답 중 취소하고 다시 생성합니다. 추가 질문에서도 같은 동작을 확인합니다.
- PDF 다운로드가 시작되지 않으면 생성 후 표시되는 **PDF 열기** 링크로 열어 저장합니다.
- 결과 PDF를 실제로 저장한 뒤 휴대폰 PDF 앱과 발표 PC에서 엽니다. 글자·사진·페이지 잘림을 확인합니다.
- 지도 인터넷 연결 실패 뒤 재시도합니다. 안경원·검안 서비스를 포함한 경우 종류가 표시되는지 확인합니다.
- 서버 저장 기능은 없습니다. PDF를 보관하기 전 탭을 닫거나 새 검사를 시작하면 결과를 다시 조회할 수 없습니다.

USB 디버깅을 이미 사용하는 Android 기기를 직접 확인할 때는 `adb devices -l`에서 허용 상태를 확인하고
`adb reverse tcp:8001 tcp:8001`로 **기기의** `http://127.0.0.1:8001/`에서 PC 앱을 열 수 있습니다.
점검이 끝나면 `adb reverse --remove tcp:8001`로 해제합니다. 앱 실행 도구는 LAN이나 인터넷에 서버를 노출하지 않습니다.

## 사진 검증

당사자가 제공에 동의한 별도 사진을 사용합니다. 진단 라벨이 확인되지 않은 사진은 라벨 없는 폴더에 넣습니다.
`normal/`·`cataract/`는 알려진 라벨이 있는 경우만 쓰고, 눈이 아닌 사진은 `non_eye/`에 둡니다.
조명·거리·흔들림·안경 여부를 바꾼 사례를 포함하되, 재촬영 요청을 정상 판정으로 세지 않습니다.

```powershell
.\.venv\Scripts\python.exe scripts\validate_real_photos.py C:\path\to\photos --report-dir C:\path\to\validation
```

결과는 지정한 로컬 폴더에 `photo-results.csv`와 `photo-summary.json`으로 내보냅니다.
사진을 복사하거나 앱의 서버 저장 기능을 되살리지 않습니다. 파일 경로가 포함되므로 공유 전에 검토합니다.
이 도구는 서버 파이프라인을 사용합니다. 브라우저 축소·전송 과정과 실제 휴대폰 촬영은 별도로 확인합니다.
오류·재촬영·판단 어려움·경계·위험·뚜렷한 특징 없음은 구분해서 기록하고, 소규모 시연 표본을 임상 정확도로 제시하지 않습니다.
