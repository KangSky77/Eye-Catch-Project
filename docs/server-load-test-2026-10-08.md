- 사진의 결과 코드가 단독 기준과 같아야 성공. 질문은 AI 생성과 규칙 대체를 구분.

이는 실제 HTTP 요청으로 서버 경로를 시험한 결과입니다. 부하 발생기와 서버가 같은 PC에 있고,
휴대폰 여러 대의 화면·카메라·PDF를 자동 조작한 시험은 아닙니다. 공개 경로도 서버 PC에서
접속했습니다. 현장 Wi-Fi, 이동통신, 외부 지도 API의 한도 및 장시간 운영은 이 수치에 포함되지 않습니다.

## 병목과 운영 판단

측정 기록은 한국 시간 14:51~15:29, 약 38.7분입니다. 기록된 사진 분석 324건,
AI 요약 184건, 추가 질문 80건, 최초 접속 묶음 435회, 상태 점검 1,968건을 수행했습니다.
최초 접속 묶음 하나는 여러 정적 파일 요청을 포함하므로 HTTP 요청 총수는 이보다 많습니다.

PC 전체 자원의 샘플링 최대는 RAM 20.84GiB, GPU 메모리 4,797MiB(약 4.68GiB), GPU 온도 72°C였습니다.
가용 RAM은 최소 10.87GiB였습니다. RAM·CPU 값은 부하 발생기와 다른 실행 프로그램도 포함합니다.
서버 프로세스는 시험 전후 같은 PID 22556이었고, 메모리 부족이나 프로세스 종료는 관찰되지 않았습니다.
이 관찰만으로 장시간 메모리 누수가 없다고 결론짓지는 않습니다.

부하 종료 뒤 단독 AI 요약은 3.53초, 2000px 사진 분석은 0.92초에 정상 완료했습니다.
`/healthz`, `/readyz`, `/api/service-status`도 모두 200과 준비 상태를 반환했습니다.

주된 병목은 **AI 추가 질문 대기와 생성·재검토**입니다.
`app/api/routes.py`에서 LLM 슬롯을 기다린 후 질문 생성을 시작하며,
`app/services/personalized_questions.py`의 40초 예산은 슬롯 대기 시간을 포함하지 않습니다.
반면 `static/app-chat.js`의 45초 제한은 대기와 응답 전체를 포함합니다.
추가 질문과 요약·챗봇이 같은 2개 슬롯을 공유하므로 전체 흐름에서 지연이 늘 수 있습니다.

부하 중에도 고정 응급 안내는 0.007초, 쉬운 결과 설명은 0.002초에 응답했습니다.
모델 생성 대기열을 거치지 않는 경로가 AI 부하 때문에 같이 멈추는 현상은 관찰되지 않았습니다.

발표 때 권장하는 운영은 다음과 같습니다.

1. **전체 체험은 2명씩 시작합니다.** 3명은 여유가 적은 상한으로 보고, 동시에 추가 질문을
   요청하는 인원이 더 늘지 않게 안내합니다. 4명 이상에게 같은 순간 전체 검사를 시작시키지 않습니다.
2. **QR 최초 접속도 소규모로 나눕니다.** 공개 주소에서 10명 모두 성공했지만 최초 자료 수신에
   약 16초 걸렸습니다. 한꺼번에 여는 경우 이 대기를 안내합니다.
3. **자동 절전을 ‘안 함’으로 설정합니다.** 최초 시험 때는 AC 15분, DC 10분이었습니다. 아래 후속 작업에서 모두 0으로 변경했습니다. 서버 PC를 조작하지 않는
   동안 요청이 오더라도 절전을 확실히 막는 구성은 이번에 확인하지 않았습니다.
4. **가능하면 유선 LAN을 사용하고 해당 연결로 재시험합니다.** 공개 경로가 로컬보다 느렸으며,
   현재 PC는 Wi-Fi에 연결돼 있습니다. PC 무선·인터넷 업로드·터널 중 정확한 병목은 분리하지 않았습니다.
5. 10월 20일에 실제 발표 PC와 휴대폰으로 사진→문진→AI→PDF를 한 번 완료하고 모델을 준비시킨 뒤,
   아래 2~3명 부하 재시험을 합니다. 포트와 터널 목적지를 같은 서버로 맞춥니다.

인원을 늘릴 때는 추가 질문의 **슬롯 대기까지 포함하는 시간 예산**과 혼잡 시 검수된 고정 질문으로
빨리 전환하는 처리가 우선 개선 대상입니다. LLM 동시 슬롯 숫자만 늘리는 방안은 검증하지 않았습니다.
위 수치는 입장 대기 기능을 적용하기 전의 측정입니다. 후속 작업에서 동시 입장을 2명으로 제한하는 대기 화면을 적용했습니다.

## 재시험과 원본

부하 도구는 이미 실행 중인 서버에만 요청합니다. 아래 명령은 로컬 서버가 준비된 뒤 실행합니다.
공개 주소를 사용하려면 `--url`을 해당 HTTPS 주소로 바꿉니다. 외부 전송량은 최초 접속 횟수에
약 3.86MB를 곱한 값이 기본이므로, 큰 최초 접속 시험은 로컬에서 먼저 수행합니다.

```powershell
.\.venv\Scripts\python.exe scripts\presentation_preflight.py --url http://127.0.0.1:8000
.\.venv\Scripts\python.exe scripts\load_test_server.py --url http://127.0.0.1:8000 --admission --language ko --respect-browser-timeouts --phase mixed:6:1 --output output\server-load-recheck
```

- 환경: [environment.json](../output/server-load-2026-10-08/environment.json)

메모리 부족은 관찰되지 않았지만, 모든 입력이나 발표 현장의 접속 환경에서 같은 성능을 보장하는
최대 접속 정원은 아닙니다. 사진 판정의 임상 정확도를 측정한 시험도 아닙니다.
