# 2026-10-02 발표 준비 점검 기록

## 반영한 변경

- 첫 화면에서 사진 분석과 AI 설명의 준비 상태를 각각 확인하고 다시 확인할 수 있습니다.
- 지도 타일 연결 실패 시 마커와 목록을 유지하며 재시도할 수 있습니다.
- 안과를 우선 표시하고, 안경원·검안 서비스는 선택한 경우에만 종류를 표시해 포함합니다.
- 한국어 화면과 PDF의 자가진단 표현을 자가검사로 정리했습니다.
- `Start-EyeCatch.cmd`와 `start.ps1`로 로컬 앱·Ollama를 준비합니다. 다른 프로그램을 종료하거나 모델을 자동 다운로드하지 않습니다.
- 사진 검증 결과를 CSV·JSON으로 내보낼 수 있습니다. 앱의 결과 저장 기능과는 별개입니다.
- PDF 생성 후 결과가 바뀌기 전까지 `PDF 열기` 링크를 제공하며, 새 검사·언어 변경·AI 재생성 시 이전 링크를 정리합니다.

응급 신호 4개는 기존 문진 순서로 유지했습니다. 서버 결과 저장 기능과 첫 화면의 졸업작품 문구는 제거된 상태입니다. 기존 저장 자료를 삭제하지 않았습니다.

## 확인한 범위

- Python 전체 검사 589개 통과, 실행 도구의 잘못된 JSON 응답 회귀 검사 4개 추가 통과.
- JavaScript 전체 검사 162개 통과. 총 755개 검사 통과.
- 실제 브라우저에서 공개 CC0 예시 사진 분석 → 양쪽 암슬러 검사 → 문진 → 실제 Ollama 맞춤 질문 → AI 설명 → 결과 화면까지 확인했습니다.
- 375px 화면·최대 글자 크기에서 가로 넘침이 없었습니다. 지도 타일 차단 후 복구도 확인했습니다.
- PDF 생성 완료, 버튼 복구, `PDF 열기` 링크 표시를 확인했습니다. 브라우저 콘솔 오류는 없었습니다.
- 서버를 최신 코드로 재시작한 뒤 `/healthz`, `/readyz`, `/api/service-status`가 모두 200을 반환했습니다. 사진·Ollama 상태는 모두 `ready`였습니다.
- 공개 예시 2장을 사진 검증 도구로 실행했습니다. 흐린 사진은 재촬영, 선명한 사진은 뚜렷한 혼탁 특징 없음으로 구분됐습니다. 이 결과는 임상 정확도 검증이 아닙니다.

## 남은 실제 기기 확인

무선 디버깅으로 연결된 SM-S938N 기기는 ADB에서 허용 상태로 확인했습니다. 휴대폰 포트 연결·Chrome 실행 명령은 자동 승인 검토가 차단했습니다. 상세 사유는 제공되지 않았습니다.

Codex 내장 브라우저는 PDF 파일 다운로드를 취소했고, PDF 링크 이동도 브라우저 보안 정책이 차단했습니다. 따라서 실제 PDF 파일의 페이지 내용·열기·저장 성공은 이번 점검에서 확인하지 못했습니다. 제한은 우회하지 않았습니다.

휴대폰의 카메라·갤러리·회전·권한 거부 후 재시도, PDF 저장·재열기와 최종 발표 PC의 전체 시연은 [점검표](presentation-checklist.md)에 따라 별도로 확인해야 합니다. 이번 실행 기록을 실기기 검증 완료로 사용하지 않습니다.
