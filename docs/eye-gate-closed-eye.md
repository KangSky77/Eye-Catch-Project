# 감은 눈 대응 — 얼굴 모드 '눈 뜸 여부' 판정기 (2026-09-13)

> **배포 구성:** 미세조정 판정기 `app/models/eye_open_cnn.pth`(아래 '미세조정 판정기')가 있으면 그것을,
> 없으면 커밋된 선형 판정기 `app/models/eye_open_gate.npz`를 쓴다. `*.pth`는 백내장 모델과 같이 git에
> 올리지 않으므로 새로 받은 저장소는 선형 판정기로 동작한다. 가중치는 `scripts/train_eye_open_cnn.py`로 다시 만든다.

## 무엇이 문제였나

얼굴 사진 모드에서 **눈을 감은 얼굴에도 백내장 판독이 나갔다.**

- AI(Gemini)로 만든 얼굴 3장 — 두 눈 감음 · 웃으며 감음 · 윙크 — 이 모두 `normal 0/100`.
  감긴 눈꺼풀 크롭의 눈 게이트 점수는 0.897~0.978로 배포 임계 0.60보다 한참 높았다.
- 실제 사진에서도 같았다. Wikimedia Commons 수면·명상 사진에서 사람이 검수한 감은 눈 크롭 중
  학습에 쓰지 않은 것의 **52~59%가 눈 게이트를 통과**했다.

원인: 눈 게이트(`app/models/eye_gate.npz`)의 음성 중 '가려진 눈'은 홍채 위에 단색 박스를 덮은
합성 이미지뿐이었다. 주름·속눈썹 선이 있는 진짜 눈꺼풀은 한 번도 배운 적이 없다.

## 왜 눈 게이트를 다시 학습하지 않았나

감은 눈을 눈 게이트의 음성 계열로 추가해 재학습해 봤다(임계 0.60).

| | 배포 게이트 | 재학습 후보 |
|---|---|---|
| 학습에 안 쓴 감은 눈 통과 | 58.9% | 21.4% |
| 정상 눈 거부 | 4.7% | **6.3%** |
| AI 생성 감은 눈 | 통과 | 여전히 통과(0.77~0.93) |

'눈이 아닌 사진'과 '감은 눈'을 한 판정기에 같이 가르치면 서로 부딪혀 뜬 눈 손해가 커졌다.
그래서 **질문을 나눴다.**

- 눈 게이트 — 이 크롭이 눈 영역인가 (그대로 둔다)
- 뜸 여부 판정기 — 눈 영역이라면 홍채·동공이 보이게 뜨고 있는가 (`scripts/build_eye_open_gate.py`)

## 동작

`app/services/vision.py` 얼굴 모드: 눈 게이트를 통과한 두 크롭 중 **하나라도 '감음'이면
`eyes_hidden`** 으로 되돌려보낸다(기존 안내 "눈이 감겨 있거나 가려진 것 같아요…"). 윙크처럼 한쪽만
감아도 두 눈 비교가 무의미하므로 막는다. 계산 실패는 눈 게이트와 같이 fail-closed(503).

클로즈업(eye) 모드에는 적용하지 않는다 — 판정기는 얼굴 사진의 눈 크롭으로 학습했다.

### 검수 (`review.json`)

`scripts/review_closed_eye_crops.py`가 앱과 같은 기하(눈 사이 거리 × 0.45 반경)로 크롭을 만들고
번호 시트를 그린다. 시트를 사람이 보고 판정했다.

- 감은 눈(`closed`): 감긴 눈꺼풀이 보이고 홍채·동공이 전혀 보이지 않는 크롭
- 뜬 눈(`open`, `excluded_open_eye`): 홍채·동공이 분명한 크롭(안경 너머라도 또렷하면 포함)
- 제외: 반쯤 뜬·찡그린 눈, 선글라스, 반사로 가려진 안경, 철조망 너머, 그림·만화·소묘·망점 인쇄,
  빛바랜 옛 사진, 코·머리카락 등 눈이 아닌 크롭, 판별 불가한 흐림 — **애매하면 제외**

'수면' 범주에도 뜬 눈이, '인물' 범주에도 감은 눈이 섞여 있었다. 반대 라벨이 들어가면 실제 사용자의
눈을 거부하게 되므로 검수는 필수다. 검수는 Claude가 시트를 보고 했으며 **사람 재확인을 권한다.**

### 분할 (`split.json`)

Commons는 같은 사진이 여러 범주에 다른 파일명으로 들어 있다. `scripts/split_closed_eye_photos.py`가
16×16 dHash 해밍 거리 20 이하를 한 묶음으로 합친 뒤 **묶음 단위**로 학습 70 / 평가 30으로 나눈다.

## 특징 비교 (평가: 뜬 눈 123 / 감은 눈 73, 뜬 눈 99% 통과 기준)

ImageNet ResNet18(눈 게이트와 같은 백본) 특징 위에 로지스틱 1층.

| 특징 | 감은 눈 거부 | 앱 흐름 감은 눈 통과 | 앱 흐름 뜬 눈 거부 |
|---|---|---|---|
| (배포 눈 게이트만) | — | 52.1% | 4.9% |
| A 마지막층 512 | 54.8% | 31.5% | 5.7% |
| B A + layer3 전체평균 | 57.5% | 28.8% | 5.7% |
| **D B + layer3·layer4 중앙평균** | **91.8%** | **6.8%** | **4.9%** |

전체 평균은 '가운데에 동공과 흰자가 있는가'라는 위치 정보를 지운다. 크롭은 MTCNN이 눈 중심에 맞춰
자르므로 중앙 영역만 따로 보면 뜸·감음이 잘 갈린다. **D를 채택했다.** 명암 통계를 더한 조합은 차이가
작아 넣지 않았다.

## 기준값 (앱 추론 코드로 재계산 — 학습 스크립트와 수치 일치)

> ⚠️ 아래 표와 위 특징 비교표는 **평가 분할에서 기준값을 고른 수치**라 낙관적이다. 학습 분할에서 사진 단위 15%를
> 검증으로 떼어 기준값을 정하고 평가에서만 재면 선형 D는 **뜬 눈 통과 97.6% / 감은 눈 거부 93.2%** (기준 0.317)였다.
> 두 판정기 비교는 이 방식으로 했다.

| 기준 | 뜬 눈 통과 | 감은 눈 거부 | 앱 흐름 감은 눈 통과 / 뜬 눈 거부 |
|---|---|---|---|
| 0.25 | 99.2% | 89.0% | 8.2% / 4.9% |
| **0.30 (배포)** | **99.2%** | **91.8%** | **6.8% / 4.9%** |
| 0.35 | 96.7% | 93.2% | 6.8% / 6.5% |
| 0.40 | 96.7% | 94.5% | 5.5% / 6.5% |

0.35로 올리면 뜬 눈 거부만 늘고 감은 눈 통과는 그대로라 0.30을 유지한다.

## 외부 확인 (학습·검수에 전혀 쓰이지 않은 사진)

| 사진 | 결과 |
|---|---|
| AI 두 눈 감음 | 거부 ✅ (뜸 0.11 / 0.08) |
| AI 윙크 | 거부 ✅ (감긴 쪽 0.14) |
| **AI 웃으며 감음** | **통과 ❌** (뜸 0.35 / 0.36) — 알려진 한계 |
| AI 뜬 눈 얼굴 6장(투명 보호대·한쪽/양쪽 백내장·안경·야간·어두운 피부) | 모두 판독 ✅ (안경 반사 한쪽은 기존 눈 게이트가 거부) |
| 저장소 `face-good.jpg` | 판독 ✅ |
| 실제 인물 크롭(측정 전용) | 눈 게이트 통과 126개 중 **판정기가 추가로 7개 거부** — 육안상 감음·거의 감음 3, 가늘게 뜸·아래 봄 2, **홍채가 보이는 뜬 눈 2(오거부)** |

웃으며 감은 눈 한 장에 맞춰 기준을 올리지 않았다 — 사진 한 장에 맞춘 임계값은 부류를 막지 못한다
(`scripts/evaluate_eye_gate.py` 상단의 도서관 사진 사례).

## 미세조정 판정기 (배포, `scripts/train_eye_open_cnn.py`)

선형 판정기는 고정 특징 위의 선 하나라 AI로 만든 **웃으며 눈 감은 얼굴**을 뜸 0.345/0.357로 통과시켰다.
ResNet18의 layer1~3은 눈 게이트와 공유(고정)하고 **layer4와 분류 헤드만 뜸 여부에 맞춰 다시 학습**했다.
추론 때는 눈 게이트 순전파의 layer3 출력을 받아 layer4 한 번만 더 계산한다. 기준값은 학습 분할에서 떼어낸
검증(사진 단위 15%)에서 정하고, 평가 분할은 재기만 했다.

| 같은 규칙(검증에서 기준 결정) | 선형 D | **미세조정(배포)** |
|---|---|---|
| 평가 뜬 눈 통과 | 97.6% | **98.4%** |
| 평가 감은 눈 거부 | 93.2% | 91.8% |
| AI 웃으며 감은 눈 (p11) | 통과 0.35 / 0.36 | **거부 0.30 / 0.65** (기준 0.664) |
| AI 두 눈 감음 · 윙크 | 거부 | 거부 |
| AI 뜬 눈 얼굴 6장 + `face-good.jpg` | 판독 | 판독 (0.98~1.00) |
| 실제 인물 크롭 추가 거부(측정 전용, 눈 게이트 통과 126개 중) | 7 | **5** |

앱 코드 경로(`eye_validator.check_eye_open`)로 다시 계산한 크롭 점수가 학습 스크립트와 일치함을 확인했다.
p11의 한쪽 눈(0.65)은 기준(0.664)에 가깝다 — 여유가 크지 않다.

기준값은 검증 뜬 눈의 1% 분위수인데 검증 뜬 눈이 43개라 사실상 **최솟값**이다. 검증 표본이 작아 기준이 흔들릴 수 있다.

### 시도했지만 채택하지 않은 것 — 웃는 얼굴 데이터 추가

p11의 여유를 늘리려고 Commons 웃음·미소 사진에서 웃으며 가늘게 뜬 눈 95개·웃으며 감은 눈 32개를 검수해 더했다.
결과는 **기준값 0.000, 평가 감은 눈 거부 42.2%** 로 망가졌다. 가느다란 틈에 반짝임만 보이는 크롭을 '뜬 눈'으로
라벨링했는데 모델이 감은 눈과 구별하지 못했고, 검증 뜬 눈이 47개뿐이라 그런 크롭 하나가 99% 통과 기준을 0으로
끌어내렸다. 경계가 분명한 웃는 얼굴 데이터를 훨씬 많이 모으기 전에는 이 방향으로 개선되지 않는다.
`scripts/fetch_smile_eye_photos.py`와 학습 스크립트의 `dataset_smileeye` 경로는 남겨 두었다 — 검수·분할 기록이
없으면 비어 있는 것으로 처리되므로 배포본 재현에 영향이 없다.

## 재현

```bash
python scripts/fetch_closed_eye_photos.py --per-category 120
python scripts/fetch_open_eye_portraits.py --per-category 80
python scripts/review_closed_eye_crops.py                        # 감은 눈 시트
python scripts/review_closed_eye_crops.py --dir dataset_openeye  # 뜬 눈 시트
# 시트를 보고 review.json 작성
python scripts/split_closed_eye_photos.py
python scripts/split_closed_eye_photos.py --dir dataset_openeye --key open
python scripts/build_eye_open_gate.py --compare

python scripts/train_eye_open_cnn.py --epochs 25 --out app/models/eye_open_cnn.pth   # 배포 판정기
```

## 한계

- 평가 표본이 작다(감은 눈 73). 수치는 방향을 보여줄 뿐 확정 성능이 아니다.
- 웃으며 감은 눈은 미세조정 판정기가 막았지만 여유가 작고(0.65 vs 기준 0.664), 선형 판정기로 대체된 환경에서는
  통과한다. 사진 확인 창("감은 눈은 다시 골라주세요")이 여전히 필요하다.
- 미세조정 가중치는 git에 없다. 새로 받은 저장소에서 같은 성능을 내려면 학습 스크립트로 다시 만들어야 한다.
- 클로즈업 모드의 감은 눈은 다루지 않는다.
- 투명 안구보호대처럼 눈이 실제로 보이는 수술 직후 사진은 막을 수 없다 — 결과 화면에
  '수술한 눈에는 적용하지 않는다'는 안내를 둔다.
- 검수는 Claude가 했다. 사람이 `review.json`을 재확인하는 것을 권한다.
